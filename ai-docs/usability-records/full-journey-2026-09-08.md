`simulated`(코드 조사 기반 starting state 위에서 상상한 시나리오)다. persona 10명을 통계적 표본으로

## 공통 지침 (모든 persona에게 동일하게 제공한 브리핑)

Research Lead가 각 persona 평가자(독립된 fresh agent, 서로의 결론을 보지 못함)에게 공통으로 제공한
내용이다. persona별 차이는 오직 "당신의 페르소나" 절과 강조 지시뿐이었다.

### 제품 배경
> AI Pixel Office는 로컬 우선 Electron 데스크톱 앱이다. Claude/Codex를 실행 엔진으로 삼아 Agent와
> Skill을 조합하고, Task를 맡기고, 진행 상태를 픽셀 오피스 화면에서 확인한다.

### 현재 구현 상태 (코드 조사 기반 starting state, 2026-09-08)
1. **설치/첫 실행**: 전용 온보딩/설치 마법사 없음. 앱 첫 실행 시 자동으로 "나의 AI 오피스" workspace가
   생성되고 바로 대시보드(오늘의 오피스)로 진입. 로딩 메시지 "오피스 문을 여는 중...". Task 0개면
   "아직 작업이 없어요" + "+ 첫 작업 만들기" CTA만 있음.
2. **AI 연결**: Settings의 "AI 연결(필수)" 섹션에서 Codex/Claude 설치·인증 상태를 신호등으로 표시.
   데스크톱: "AI 준비하기"(설치), "로그인하고 연결하기" 버튼. 브라우저 전용: 터미널 명령 복사
   아코디언(`codex login`, `claude auth login`). 사이드바 네비게이션으로 직접 찾아가야 하며 첫 실행 시
   강제 안내는 없음.
3. **Project 연결**: 프로젝트 생성 시 "작업 폴더" 필드 필수. 폴더 선택기로 연결하면 폴더명이 프로젝트
   이름으로 자동 채워짐. 폴더 미연결 레거시 프로젝트는 "연결 필요" 배지, 연결 전엔 Task 생성 불가.
4. **Agent/Skill 구성**: Agent 생성 폼에서 이름/역할/설명, 모델(codex/claude), reasoning effort, pet
   아바타, skill 다중 선택, 권한(fileRead/fileWrite/terminal, 기본 모두 허용) 설정. Skill 페이지는 카드
   그리드 + 생성 폼(이름/카테고리/설명/권한)의 일반 CRUD.
5. **Task 생성/실행**: 대시보드 다이얼로그 또는 프로젝트 상세 인라인 폼에서 Task 생성 → 담당 Agent는
   다음 화면에서 선택(2단계). 진행 표시, 실패, 세션 한도, 승인 요청(명령어 표시 + "이번만 승인"/"거절")
   상태별 화면 분리. 오피스 화면에서 Agent에게 드래그/퀵어사인으로 즉시 Task 생성 가능(마우스/드래그
   의존 상호작용).
6. **결과 검토/후속 요청**: 결과 뷰, 과거 실행 이력, 워크플로 단계 진행 확인 가능. Task 세션
   작성기로 후속 지시 입력 또는 별도 채팅 라우트(`/chat`, `/chat/:taskId`)로 대화형 후속 요청.
7. **재방문**: 루트 화면이 곧 대시보드. 실시간 픽셀 오피스 시각화, 상태별 작업 보드(할 일/진행/검토
   필요/입력 필요/막힘/실패), 오늘 완료 목록, 최근 활동 로그(필터 가능).

### 테스트 프로토콜 (공통 규칙)
- Mode: simulation — 실제 시간 경과를 가장하지 않고 Day별 목표를 압축 실행, evidence_type은
  전부 `simulated`.
- 각 persona는 다른 persona의 결론을 보지 않고 독립적으로 판단(격리된 fresh agent로 구현).
- 관찰 가능한 행동(클릭/입력/대기/되돌아감/포기)만 시간순 기록, 내적 사고는 꾸며 쓰지 않음.
- 각 Day 끝에 outcome(success/partial/failure), friction_points, trust_change(up/down/unchanged),
  return_intent 기록.
- 심각도: S0(의견/미세 불편) · S1(느려지지만 스스로 완료) · S2(반복 오류/상당한 우회 필요) ·
  S3(핵심 과업 실패) · S4(데이터·보안·신뢰 중대 위험).
- 나이·직업 고정관념을 연기하지 않고 문서화된 목표·경험·제약·관찰 관점만 적용.

### 체크포인트 (Full journey, 5일)
- Day 1: 설치, 실행, AI 연결 이해
- Day 2: 프로젝트·Agent·Skill 구성
- Day 3: 첫 Task 생성, 실행, 권한 대응
- Day 4: 결과 검토, 후속 요청, 실패 복구
- Day 5: 재방문, 진행 상황 재파악, 기록 탐색
