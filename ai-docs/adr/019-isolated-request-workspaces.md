# ADR 019: 파일을 고치는 기안서는 자기 작업 공간(git worktree)에서 실행한다

## 상태

Accepted — 2026-10-05

구현 — 작업 공간 만들기, 준비 명령과 가져올 파일, 작업 공간 안 실행, 변경 사실, 결재 반영과 충돌 검사, 기안서 삭제 시
버리기, 앱 시작 시 정리를 서버에 구현했다(2026-10-05). 작업 공간별 미리보기와 화면 표시는 아직이다. [ADR 013](./013-baseline-and-rollback.md)의 기준점 방식을 대체한다. 013에서 검증한 스냅샷 기법
(임시 index와 `write-tree`, `core.autocrlf=false`)은 작업 공간의 시작점을 만드는 데 재사용한다.

## 맥락

Pixel Office는 Orca와 Agent Orchestrator(AO)처럼 여러 AI 동료가 동시에 일하는 도구를 목표로 한다. 두 도구의
효율은 세션마다 별도 git worktree를 두어 변경이 섞이지 않게 하는 데서 나온다.

지금 구조는 동료가 사용자 프로젝트 폴더를 직접 고친다. 그래서 다음이 불가능하다.

- 같은 프로젝트에서 기안서 여러 개를 동시에 진행하기([ADR 018](./018-request-run-rules.md) 1절은 이 때문에 순서 대기를 뒀다)
- 기안 취소(결재 전 변경 버리기). ADR 013에서 보류했다
- "이 기안서가 무엇을 바꿨는지"를 정확히 보여주기([ADR 012](./012-evidence-based-state.md) 변경 사실)

격리는 개발자에게는 병렬을, 비개발자에게는 "결재하기 전에는 내 프로젝트가 바뀌지 않는다"는 안전을 준다.

## 결정

### 1. 작업 공간

- Git 저장소에 속한 프로젝트의 기안서는 시작할 때 자기 작업 공간을 만들고 모든 단계를 그 안에서 실행한다.
  파일을 고치지 않기로 한 단계가 실수로 파일을 써도 사용자 폴더에 닿지 않게 하기 위해서다.
- 작업 공간은 사용자 저장소 밖, 앱 데이터 아래 `workspaces/<projectId>/<taskId>`에 둔다.
- 시작점은 **기안서를 시작한 순간 사용자 폴더의 상태**다. 커밋된 내용에 커밋하지 않은 변경(무시된 파일 제외)을
  더한 스냅샷 커밋을 만들고, 그 커밋으로 `git worktree add --detach`한다. 사용자가 커밋하지 않은 작업 위에서
  동료가 일하게 하기 위해서다.
- 시작점은 `refs/pixel-office/requests/<taskId>/base` 참조로 보존한다. 사용자 branch 목록에는 아무것도 추가하지 않는다.
- 동료의 실행 경로는 작업 공간 안에서 프로젝트 폴더에 해당하는 경로다. 프로젝트(scope)는 그대로이고 실행
  경로만 바뀐다([ADR 005](./005-explicit-workspace-scope.md)의 실행 경로 계약 개정).
- "프로젝트 없이 대화"는 작업 공간을 만들지 않는다.

### 2. 작업 공간 준비

작업 공간에는 무시된 파일(`node_modules`, `.env` 등)이 없다.

- **준비 명령**: lockfile을 보고 앱이 제안한다(`pnpm-lock.yaml` → `pnpm install` 등). 사용자는 프로젝트 설정에서 바꿀 수 있다.
  시간이 드는 명령이므로 기안서 시작이 아니라 첫 파일 수정 단계 직전에 한 번 실행한다.
- **가져올 파일**: 프로젝트 폴더에서 작업 공간으로 복사할 무시된 파일 목록(예: `.env.local`). 기본값은 비어 있고,
  프로젝트에 `.env*` 파일이 있으면 설정 화면에서 제안한다.
- 준비 중에는 "작업 공간 준비 중"으로 표시한다. 준비가 실패하면 기안서는 첫 단계 전에 멈추고 실패 출력을 보여준다
  (ADR 012 4절 1번과 같은 "실패하여 판단 필요").
- 화면에는 branch, worktree, merge 같은 용어를 쓰지 않는다. 사용자에게는 "작업 공간"과 "결재하면 반영"으로만 보인다.

### 3. 변경 사실

- 변경 사실은 시작점 커밋과 작업 공간 현재 상태(커밋하지 않은 변경 포함, 무시된 파일 제외)의 차이다.
- 프로젝트 폴더 밖(같은 저장소의 다른 폴더) 변경은 따로 표시하고 결재 때 반영하지 않는다.
- ADR 018 3절의 "변경 사실이 있으면 결재 대기"는 이 차이로 판단한다.

### 4. 결재 = 사용자 폴더에 반영

- 결재하면 시작점 → 작업 공간의 차이를 사용자 프로젝트 폴더에 **커밋하지 않은 변경으로** 적용한다. commit이나
  PR을 만들지 않는다(W1 결정과 같음).
- 적용 전에 충돌 여부를 먼저 검사한다. 사용자 폴더가 그사이 바뀌어 겹치면 반영하지 않고
  "먼저 반영된 변경과 겹쳐요"로 멈춘다. 이때 사용자는 "단풍에게 맞춰 달라고 하기"를 고를 수 있다. 앱은 사용자 폴더의
  현재 상태로 새 시작점을 만들어 작업 공간에 기존 변경을 옮기고, 겹친 부분은 담당 동료가 작업 공간 안에서 해결한다.
- 충돌 표시가 사용자 폴더에 남는 적용 방식은 쓰지 않는다.

### 5. 끝내기

- 결재로 반영하거나 기안 취소하면 작업 공간과 참조를 지운다. 취소는 사용자 폴더에 아무 흔적도 남기지 않는다.
- 반려(수정 요청)는 같은 작업 공간에서 이어간다.
- 앱 시작 시 끝난 기안서의 작업 공간이 남아 있으면 정리한다.

### 6. 병렬

- Git 저장소 프로젝트에는 ADR 018 1절의 파일 수정 자리를 두지 않는다. 같은 프로젝트에서 여러 기안서가 동시에 진행된다.
- 동시에 실행하는 동료 수의 상한은 앱 설정으로 둔다. 상한을 넘으면 "순서 대기"로 보인다.
- Git 저장소가 아닌 폴더는 격리할 수 없으므로 ADR 018 1절의 순서 대기 규칙을 그대로 쓴다.

## 검증 기록 (2026-10-05, Windows Git, 임시 저장소)

임시 저장소에 커밋하지 않은 수정, 추적하지 않는 파일, 무시된 파일(`node_modules/`, `.env.local`)을 둔 상태에서
다음을 확인했다(16개 항목 모두 통과).

- 임시 `GIT_INDEX_FILE`로 만든 시작점 스냅샷 커밋은 사용자 index와 branch 목록을 바꾸지 않는다.
- `git worktree add --detach <앱 데이터 경로> <스냅샷 커밋>`으로 만든 작업 공간에는 사용자의 커밋하지 않은 수정과
  추적하지 않는 파일이 있고, 무시된 파일은 없다.
- 작업 공간을 같은 방식으로 스냅샷해 시작점과 비교하면 수정·추가·삭제가 나오고 무시된 파일은 나오지 않는다.
- `git diff --binary <시작점> <작업 공간 스냅샷>`을 사용자 폴더에 `git apply`하면 커밋 없이 반영되고, 사용자의
  다른 커밋하지 않은 수정은 그대로 남는다.
- 사용자 폴더가 그사이 같은 줄을 바꿨으면 `git apply --check`가 실패하고 사용자 폴더는 바뀌지 않는다.
- `git worktree remove --force`, `update-ref -d`, `worktree prune` 뒤 작업 공간과 참조가 남지 않는다.

## 결과

- 기안 취소가 가능해진다. ADR 013의 되돌리기 보류를 이 방식으로 해소한다.
- Orca의 "같은 요청을 여러 동료에게 맡겨 비교하기", AO의 "요청을 나눠 여러 기안서로 배분하기" 같은 오케스트레이션을
  이 작업 공간 위에서 만들 수 있다.
- 프로젝트 설정에 준비 명령과 가져올 파일이 필요하다([ADR 017](./017-project-centered-workspace.md) 2절).
- 기안서마다 준비 명령을 실행하므로 시작이 느려지고 디스크를 더 쓴다. 준비 시간과 사용량은 기준선 측정에서 확인한다.
- 미리보기(개발 서버)는 작업 공간마다 따로 띄워야 하며 별도로 다룬다.

## 재검토 조건

- 준비 시간이 사용자가 기다릴 수 없는 수준으로 측정될 때(공유 폴더 연결 같은 최적화 검토)
- 결재 충돌이 잦아 "맞춰 달라고 하기"가 반복될 때
- Git 저장소가 아닌 프로젝트 사용자가 주요 대상으로 확인될 때
