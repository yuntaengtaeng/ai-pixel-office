# ADR 016: Agent Orchestrator의 운영 원칙을 도입하되 모든 직군이 쓰는 말과 작업으로 옮긴다

## 상태

Accepted — 2026-10-04

원칙별 적용 시점은 아래 표의 "적용"에 적는다. 원칙 8은 [ADR 020](./020-project-lead-delegation.md)에서 프로젝트마다 있는
팀장으로 앞당겨 적용하고, 고정 팀(Workflow 단계)을 대체한다(2026-10-05).

## 맥락

Agent Orchestrator(AO)는 여러 AI 코딩 Agent를 운영하는 데스크톱 앱이다. 조사 결과(2026-10-04, 레포의
README, DESIGN.md, docs, Go 소스) AO의 강점은 기능 목록보다 운영 원칙에 있다. 상태를 사실에서 계산하고, 각
런타임의 장점을 그대로 쓰고, 기계가 판단할 수 있는 실패는 Agent에게 되돌려 보내고, 사람만 할 수 있는 결정은
반드시 사람에게 남긴다.

다만 AO는 개발자 전용이다. worker, session, PR, CI, merge, worktree가 화면의 언어이고, 공유 수단이 없으며,
코드가 아닌 일은 다루지 않는다. Pixel Office의 사용자는 PM, PO, Designer와 그 밖의 직군을 포함한다
([ADR 011](./011-target-user-and-w1.md)). 그래서 원칙은 가져오되 화면의 언어([ADR 015](./015-visual-language-graphite-approval-office.md))와
대상 작업은 모든 직군에 맞게 옮긴다.

### 따르지 않는 것

- 개발자 용어와 Terminal·TUI 중심 화면을 기본으로 보여주지 않는다. Developer Mode에서만 보여준다.
- 공유 수단이 없는 구조를 따르지 않는다. Team과 Skill은 패키지로 공유한다([ADR 014](./014-native-skill-and-team-packages.md)).
- 개발 작업만 대상으로 하지 않는다. 다음 대표 Workflow(W2)는 코드가 없는 직군의 일에서 고르는 것을 우선 검토한다.

### 모든 직군을 위한 해석 규칙

AO 원칙을 새 기능에 적용할 때 다음 질문에 답한다.

1. 이 원칙의 "사실"은 코드가 없는 일에서 무엇인가? (예: 테스트 통과 → 수용 조건 체크, 검토 담당 의견, 문서 변경 내역)
2. 이 화면은 개발 용어 없이 설명되는가? (ADR 015의 화면 언어)
3. 이 동작이 사람의 판단을 대신하는가? 대신한다면 원칙 4를 어기지 않는가?

## 결과

- [ADR 012](./012-evidence-based-state.md)의 Output Contract 수집은 보고 도구를 우선한다(원칙 2). 확인 실패 시
  자동으로 한 번 되돌려 보내는 규칙(원칙 3)은 ADR 012의 단계 진행 규칙 4번을 개정한다.
- 런타임 adapter는 보고 도구를 제공할 수 있어야 한다. Claude Agent SDK는 앱 내부 MCP 도구로, Codex는 MCP 서버
  설정으로 제공하는 방안을 구현 시 확인한다.
- 팀장 비서(원칙 8)와 검토 담당(원칙 9)은 Product Team과 같은 Team 패키지 형식의 역할로 추가한다.
- 일반 작업 공간의 기준점(원칙 12)은 앱이 소유한 폴더이므로 ADR 013의 "사용자 폴더에 저장소를 만들지 않는다"와
  충돌하지 않는다. 적용할 때 ADR 013을 개정한다.

## 재검토 조건

- 비개발자 사용성 검증에서 원칙 3의 자동 되돌려 보내기나 원칙 8의 계획 결재가 오히려 이해를 어렵게 한다고 확인될 때
- AO가 원칙을 바꾸거나, 더 나은 사례가 확인될 때(이 ADR은 AO를 따르는 것이 아니라 원칙을 채택한 것이다)
