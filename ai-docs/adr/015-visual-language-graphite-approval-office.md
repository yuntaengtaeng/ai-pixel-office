# ADR 015: 시각 언어는 "그래파이트 결재 오피스"로 한다

## 상태

Accepted — 2026-10-04

진행 중 — design token, 공통 primitive, 사이드바, 오피스 평면도 첫 화면(내 자리 앞 대기 줄과 걷기 동작 포함)과 결재함,
조직도와 사원증, 교육 자료실, 기안서 결재란, 시작 화면을 적용했다(2026-10-05). 기안서 본문, 메신저, 프로젝트, 기록,
인사평가, 설정, 온보딩은 아직 이전 배치다.

## 맥락

기존 화면은 따뜻한 종이 톤 배경, 2px 테두리와 오프셋 그림자, 나무 바닥 오피스로 "귀여운 픽셀 오피스"를
표현했다. 제품 방향이 바뀌면서([ADR 011](./011-target-user-and-w1.md)) 화면은 AI 팀의 판단 요청과 근거를
빠르게 읽는 업무 도구여야 한다. 시안 세 가지를 비교했다.

- A안: Agent Orchestrator(AO)와 같은 사이드바 + 목록 + 칸반 문법, 어두운 그래파이트 톤. 분위기는 좋지만
  AO를 따라 한 인상이 강했다.
- B안: 같은 규칙을 한국 회사 은유(결재함, 기안서, 결재란, 도장, 전결, 조직도, 사원증)로 옮긴 화면. 구조와
  언어는 독창적이었지만 밝은 회색 그룹웨어 색은 칙칙했다.
- 결정안: B안의 구조와 언어에 A안의 그래파이트 색과 질감을 입힌다.

## 결정

### 1. 콘셉트

**최신 사무실에 끌려온 픽셀 팀.** 환경(UI, 오피스 공간)은 고해상도의 어두운 정밀 도구이고, 픽셀은 동료
캐릭터와 이름표에만 쓴다. 두 해상도의 대비가 정체성이다.

### 2. 화면 언어 — 회사 은유

[ADR 012](./012-evidence-based-state.md)의 상태와 사람의 행동을 다음 말로 보여준다. 구현 용어를 쓰지 않는다는
[ADR 011](./011-target-user-and-w1.md) 원칙을 회사 말로 지키는 방식이다.

| 제품 개념                                                     | 화면 언어                                                  |
| ------------------------------------------------------------- | ---------------------------------------------------------- |
| Human Desk                                                    | 결재함                                                     |
| 권한 요청 / 사용자 질문 / 확인 실패 / 결과 불완전 / 중간 확인 | 권한 요청서 / 질의서 / 실패 보고서 / 보완 요청 / 중간 결재 |
| 최종 검토 결과                                                | 기안서                                                     |
| Workflow                                                      | 결재 라인                                                  |
| 정상 자동 진행                                                | 전결                                                       |
| 승인 / 수정 요청 / 되돌리기                                   | 결재 / 반려 / 기안 취소                                    |
| Agent 목록, Team                                              | 조직도, 사원증                                             |
| Skill 라이브러리                                              | 교육 자료실, 이수 교육                                     |
| 런타임 연결                                                   | 출근                                                       |

은유는 행동 이름과 서류 종류에만 쓴다. 상태 설명 문장은 평범한 말로 쓴다(예: "테스트 2개가 실패해서
멈췄어요"). Developer Mode와 "세부 정보"는 원래 용어를 쓴다.

### 3. 색

- 면: 어두운 그래파이트 단계(캔버스 → 표면 → 올린 표면). 경계는 1px의 낮은 대비 선이다.
- 상태 색은 의미가 있을 때만 쓴다: 파랑 = 진행, 주황 = 사람의 판단 필요(도장 색과 같음), 노랑 = 질문,
  초록 = 통과·완료, 빨강 = 실패.
- 주요 행동은 밝은 중립색 버튼 하나다. 도장 색 버튼은 결재(최종 승인)에만 쓴다.
- 픽셀 캐릭터와 오피스 콘텐츠의 색은 UI theme이 아니라 콘텐츠 팔레트로 따로 관리한다(`design-system.md`의
  기존 원칙 유지).

### 4. 형태와 질감

- 테두리 1px, 모서리 8~14px. 오프셋(하드) 그림자를 쓰지 않는다. 그림자는 Dialog, Popover처럼 떠 있는 층에만
  쓴다.
- 서류(기안서, 결재함 카드)는 종이처럼 보이지 않고 표면 단계와 명조 제목으로 구분한다.
- 결재란과 도장은 시각 정체성의 핵심 요소다. 도장은 원형 테두리 + 이름, 약간 기울인 모양이다.

### 5. 글꼴

- 본문: Pretendard. 앱에 함께 배포한다(`pretendard` 패키지의 가변 글꼴, 쓰는 글자 범위만 불러오는 dynamic subset).
  불러오기 전이나 실패하면 시스템 한글 산세리프(`Apple SD Gothic Neo`, `Malgun Gothic` 순)로 대체한다(2026-10-05).
- 서류 제목과 도장: 시스템 명조(`Noto Serif KR`, `AppleMyungjo`, `Batang` 순).
- 숫자, 문서 번호, 경로: 모노스페이스.
- 동료 이름표: 픽셀 글꼴. 오프라인에서도 같은 모양이어야 하므로 OFL 픽셀 글꼴을 앱에 포함할 때까지
  모노스페이스로 대체한다.
- 로컬 우선 앱이므로 원격 글꼴(Google Fonts 등)을 실행 중에 불러오지 않는다.

### 6. 화면 구조

왼쪽 사이드바(업무: 오피스 · 결재함 · 메신저 · 프로젝트 / 팀: 조직도 · 교육 자료실 / 자료: 기록 · 인사평가,
아래에 런타임 출근 상태와 설정)와 오피스 평면도 첫 화면을 기준으로 한다. 상단 바는 쓰지 않는다.
오피스는 상태의 원본이 아니며, 같은 상태를 결재함과 기안서에서 텍스트로 확인할 수 있다(ADR 009 접근성 원칙).

## 결과

- `packages/design-token`의 색 키 구조는 유지하고 값을 바꾼다. 도장 색처럼 새 역할만 키를 추가한다.
- `packages/design-system`의 Button, Panel, Surface, Dialog, Input에서 2px 테두리와 오프셋 그림자를 걷어낸다.
- `apps/web`에 직접 쓰인 2px 테두리와 오프셋 그림자를 정리한다.
- ADR 009의 사이드바 정보 구조는 유지하되 메뉴 이름과 그룹은 6절을 따른다. 시각 규칙 중 이 ADR과 다른 부분은 이 ADR이
  대체한다. 접근성 원칙은 유지한다.
- 오피스 장면(`canvasScene.ts`)과 시작 화면(`CommuteSplash.tsx`)은 콘텐츠 팔레트이므로 화면 구조 개편 때 평면도
  스타일로 다시 그린다.
- 밝은 테마는 지금 제공하지 않는다. 필요해지면 같은 키로 두 번째 값 세트를 추가한다.

## 재검토 조건

- 사용성 검증에서 다크 화면이 비개발자 사용자의 장시간 사용에 불편하다고 확인될 때
- 회사 은유가 해외 사용자나 특정 사용자층에게 이해되지 않는다고 확인될 때
- 시스템 글꼴 차이로 플랫폼 간 화면이 크게 달라질 때(글꼴 포함 결정)
