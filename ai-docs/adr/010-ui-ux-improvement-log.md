# ADR 010: UI/UX 개선 실행 기록

## 상태

Active — 2026-09-06

## 목적

ADR 009에서 결정한 UI/UX 개선을 실제 화면에 적용하면서, 무엇을 왜 바꾸었는지와 검증 결과를 남긴다. 이 문서는 새로운 디자인 결정을 만드는 문서가 아니라 실행 순서와 변경 이력을 기록하는 문서다.

## 적용 범위

다크모드는 현재 제품 범위에 포함하지 않는다. 나머지 리뷰 항목은 다음 순서로 진행한다.

1. 최초 실행 온보딩과 실행 불가 원인 안내
2. Task 상세의 대표 액션 및 실패 복구 흐름
3. 공통 Task Composer와 Empty State
4. Sidebar·모바일 Chat 정보 구조
5. 카드 밀도, 토큰, 오피스 접근성·상태 범례
6. 기록·성과 화면의 제품 정체성 강화

## 실행 원칙

- 기존 사용자 변경을 보존하고 한 단계씩 작은 범위로 적용한다.
- 공통 UI는 design-system primitive와 token을 우선 사용한다.
- 공통화하더라도 호출 위치의 context(프로젝트, 담당자, 대화)를 잃지 않는다.
- 오피스의 픽셀 캐릭터성과 일반 UI의 정보 계층을 억지로 하나의 스타일로 합치지 않는다.
- 각 단계마다 관련 typecheck/test와 화면 확인을 수행한다.

## 변경 기록

### 2026-09-06 — 리뷰 결과와 범위 확정

- UI/UX 디자이너 리뷰와 Claude 리뷰를 ADR 009에 기록했다.
- 다크모드 지원은 예정이 없으므로 범위에서 제외했다.
- P0부터 진행하기로 결정했다.
- 현재 Today 화면의 작업 없음 상태 CTA는 이미 존재하므로, 온보딩에서는 이를 중복하지 않고 연결 상태·에이전트·작업 폴더까지 이어지는 체크리스트로 확장한다.

## 다음 작업

첫 구현은 Today의 최초 실행 체크리스트다. 완료한 단계는 재방문 시 반복 노출하지 않고 축약 상태로 보여주며, 각 단계는 실제 해결 화면으로 이동하는 CTA를 제공한다. 이후 실행 버튼의 비활성화 원인과 해결 CTA를 Task Composer 및 Task 상세에 연결한다.

### 2026-09-06 — Today 최초 실행 체크리스트 (보류)

- 초기 구현한 체크리스트는 완료 여부를 안내하는 수준이라 사용자에게 노출하지 않기로 했다.
- 기존 작업 없음 상태 CTA는 유지한다.
- 체크리스트 코드는 제거하고, 실제 예시 작업까지 안내하는 전용 Onboarding Dialog/Page로 재설계한다.
- 이번 단계에서는 불완전한 온보딩 UI를 숨기는 것으로 마무리했다.
- `pnpm --filter @ai-pixel-office/web typecheck` 통과.

### 2026-09-06 — 실행 불가 원인 안내 (재검토)

- 액션 바에 원인 문구와 `에이전트 설정` CTA를 추가했으나, UI/UX 리뷰 재검토 결과 핵심 액션의 우선순위를 흐리는 것으로 판단했다.
- 기존의 간결한 액션 바를 복원하고, 담당자 문제는 Assignment 패널, 권한 문제는 Permission Warning 영역에서 해결하도록 책임을 분리한다.
- `/agents`로 보내는 넓은 이동보다 현재 Task의 담당자 선택 영역으로 직접 유도하는 방식을 다음 구현으로 검토한다.
- `pnpm --filter @ai-pixel-office/web typecheck` 통과 예정.

### 2026-09-06 — Todo Task 상세 1차 단순화

- UI/UX 디자이너 재검토 결과 `todo`를 결과 화면이 아니라 실행 준비 화면으로 정의했다.
- 실행 전에 의미가 없는 실행 기록, 최근 실행, 토큰·개발자 옵션을 `todo` 화면에서 숨겼다.
- WorkflowPanel 안의 담당자 선택과 중복되는 현재 담당 에이전트 카드를 `todo`에서 숨겼다.
- 작업 목표, 담당자 선택, 프로젝트, 우선순위, Workflow, 참고 문서·실행 Context, 권한 복구, 삭제는 실행 결과에 영향을 주므로 유지했다.
- 다음 리팩터링에서는 상태별 본문을 `TodoTaskView`, `ActiveTaskView`, `ReviewTaskView`, `ResultTaskView`로 분리하되 헤더·오류·삭제 계약은 공유한다.
- `pnpm --filter @ai-pixel-office/web typecheck` 통과 예정.

### 2026-09-06 — Todo 실행 준비 화면 분리

- `TaskTodoView`를 독립 컴포넌트로 분리해 작업 목표 입력·임시 저장·작업 시작 책임을 한곳에 모았다.
- Todo에서는 상단 sticky 액션 바를 제거하고 작업 목표 입력 하단에 Primary Action을 배치했다.
- 작업 시작 시 변경된 요청이 자동 저장되는 기존 실행 계약을 UI 문구로 명확히 했다.
- 담당자나 권한이 준비되지 않은 경우 해결 위치를 짧게 안내하되 별도 경쟁 CTA는 추가하지 않았다.
- 오른쪽 패널은 `실행 준비`로 명명하고 담당 방식·프로젝트·실행 Context·권한 복구를 유지했다.
- `frontend-code-style`의 책임 기반 컴포넌트 분리와 design-system primitive/token 규칙을 적용했다.
- `pnpm --filter @ai-pixel-office/web typecheck` 통과.

### 2026-09-06 — Task 상세 메시지 흐름과 실행 정보 정리

- 작업 목표와 후속 요청을 모두 에이전트에게 보내는 메시지 흐름으로 정리했다. Todo의 목표 입력은 메시지 composer 형태로, 검토 단계의 후속 요청은 같은 표면·테두리 규칙의 compact composer 형태로 제공한다.
- 상태가 달라져도 상단 Primary Action 위치는 유지했다. Todo는 같은 위치에서 `작업 시작`을 제공하고, 실행 준비가 되지 않은 경우에만 해당 버튼을 비활성화한다.
- 기존의 중첩된 실행 Context·참고 문서 목록·개발자 옵션을 `실행 정보` 접이식 패널 하나로 합쳤다. 닫힌 상태에서는 작업 폴더·스킬·최근 토큰을 한 줄로 요약하고, 열었을 때 폴더·지침·스킬·참고 문서·입출력 토큰을 동일한 행 구조로 보여 준다.
- 참고 문서 선택은 인라인 details 대신 검색·체크박스 기반 Dialog로 분리했다. 이 작업에서 생성한 문서는 포함 상태로 잠그고, 사용자가 추가한 문서만 연결을 변경할 수 있다.
- UI/UX 리뷰의 “공통 상세 골격 유지”, “설정은 요약 후 필요할 때 확장”, “참고 문서는 별도 관리” 의견을 반영했다.
- `pnpm --filter @ai-pixel-office/web typecheck` 통과.

### 2026-09-06 — Task 상세 공통 골격 재정렬

- UI/UX 재검토 결과, Todo가 독립적인 작성 화면처럼 보이고 상태별로 우측 정보의 순서와 대표 행동이 달라져 같은 Task의 상태 변화로 느껴지지 않는 문제를 확인했다.
- Todo의 작업 요청 composer에서 빈 상태용 보조 상자와 과도한 높이를 제거해 본문 패널의 밀도를 실행·검토·결과 상태와 맞췄다.
- 모든 상태에서 상단 Primary Action Bar를 유지하고 Todo는 시작, 실행 중은 취소, 실패는 재시도, 그 외에는 문서화를 대표 행동으로 제공하도록 정렬했다.
- 우측 패널의 제목을 상태와 무관한 `작업 정보`로 고정했다. 실행 정보·참고 문서·워크플로우가 상태 전환 뒤에도 같은 영역에 남도록 했다.
- 실행 기록과 토큰처럼 실행 전 의미가 없는 정보는 보이지 않게 두되, 영역 자체를 다른 페이지처럼 제거하지 않는 원칙을 적용했다.

### 2026-09-06 — Task 상세를 세션 대화로 전환

- Task는 단순한 티켓이 아니라 사용자가 AI와 요청·결과·후속 요청을 이어 가는 하나의 세션이라는 제품 모델을 본문 UI에 반영했다.
- 실행이 시작된 Task 상세 본문은 별도 결과 카드와 실행 기록 대신 기존 메시지 스레드를 사용한다. 사용자 요청과 에이전트 결과·실패·진행 상태가 시간 순서의 대화로 이어진다.
- `이어서 요청` composer는 이 스레드의 다음 사용자 메시지로 계속 동작한다. 실행 설정은 오른쪽 패널에 남겨 대화와 설정을 분리했다.
- `pnpm --filter @ai-pixel-office/web typecheck` 및 대상 ESLint 통과.

### 2026-09-06 — 세션 메시지 발신 UI 통일

- 최초 작업 목표와 `이어서 요청`은 모두 사용자가 AI 세션에 보내는 메시지이므로 같은 composer 위계를 적용했다.
- Todo의 최초 요청은 재사용 가능한 `TaskSessionComposer`로 분리했다. 후속 요청도 단일 줄 입력 대신 동일한 textarea 밀도·표면·전송 버튼 규칙으로 바꿨다.
- 결과적으로 사용자는 Task 생성 직후와 결과 검토 뒤 모두 같은 방식으로 메시지를 작성하고 전송한다.
- `pnpm --filter @ai-pixel-office/web typecheck` 및 대상 ESLint 통과.

### 2026-09-06 — 세션 타임라인 스크롤 영역

- Task 상세의 대화 타임라인은 채팅방처럼 최대 높이를 가지는 독립 스크롤 영역으로 제공한다.
- 섹션 제목과 Task의 상단 대표 액션은 유지하고, 누적되는 요청·응답·진행 메시지만 내부에서 스크롤한다.
- 후속 요청 composer는 타임라인 바깥 하단에 배치해 내부 메시지 스크롤과 함께 움직이지 않도록 했다.

### 2026-09-06 — 모바일 탐색 구조 (보류)

- Chat 외 Today·Project·Office의 모바일 전환 규칙 수립과 Sidebar의 drawer/bottom navigation 전환은 이번 라운드에서 보류한다.
- Office처럼 캔버스 기반 화면의 모바일 재구성(줌/팬 유지 여부, 접근 가능한 작업 리스트의 모바일 기본 노출 여부)은 별도 설계가 필요해 다음 라운드로 미룬다.
