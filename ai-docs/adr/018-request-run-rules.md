# ADR 018: 기안서 진행 규칙 — 프로젝트당 파일 수정 하나, 메시지 전달, 결재 조건

## 상태

Accepted — 2026-10-05

2절은 [ADR 020](./020-project-lead-delegation.md)에 따라 단계형 기안서와 함께 폐기한다(2026-10-05).

구현 — 2절(메시지 전달, `packages/domain/src/message-routing.ts`), 3절(결재 조건, `request-engine/stage-decision.ts`),
화면의 받는 사람 선택과 전달 안내를 구현했다(2026-10-05). 1절은 [ADR 019](./019-isolated-request-workspaces.md)에 따라
Git 저장소가 아닌 프로젝트에만 적용한다. 같은 폴더에 결재 전 변경을 가진 다른 기안서가 있으면 기안서를 시작 전 상태로 두고
앞 기안서 이름을 `Task.queuedBehind`에 남겨 순서 대기로 만든다(`apps/server/src/request-queue.ts`). 앞 기안서가 완료·실패·
삭제되어 자리가 비면 먼저 기다린 기안서부터 자동으로 이어간다. 결재 대기 중 중간 확인을 결재해 다음 단계를 시작할 때 자리가
차 있으면 대기로 바꾸지 않고 사유를 알린다.

## 맥락

[ADR 017](./017-project-centered-workspace.md)로 화면이 프로젝트와 대화 중심이 되면 세 가지 질문이 생긴다.

1. 같은 프로젝트에서 여러 기안서가 동시에 진행되면 같은 폴더의 파일을 함께 고친다. 결재 전 변경이 섞이면
   "이 기안서가 무엇을 바꿨는지"([ADR 012](./012-evidence-based-state.md) 변경 사실)를 보여줄 수 없다. AO는 세션마다
   branch/worktree를 두어 이 문제를 풀지만, Pixel Office는 격리 실행을 미뤘다([ADR 013](./013-baseline-and-rollback.md)).
2. 모든 기안서가 대화가 되면 사용자는 Workflow 진행 중에도 말을 걸 수 있다. 아직 차례가 오지 않은 동료에게
   보내거나 앞 단계 결과를 뒤집는 말이 들어오면 단계 계약과 자동 진행이 흐트러진다.
3. 폴더를 고른 대화가 모두 결재를 거치면 프로젝트에 질문만 해도 결재란이 붙는다.

## 결정

### 1. Git 저장소가 아닌 프로젝트에서는 파일을 고치는 기안서를 한 번에 하나만 진행한다

Git 저장소 프로젝트는 기안서마다 작업 공간을 두어 동시에 진행한다(ADR 019). 이 절은 격리할 수 없는 폴더에만 적용한다.

- 프로젝트마다 "파일 수정 자리"가 하나 있다. 파일을 고치는 단계가 시작될 때 자리를 잡고, 기안서가 결재로
  끝나거나 취소될 때 놓는다.
- 자리가 차 있으면 기안서는 파일을 고치는 단계 직전에 멈추고 "순서 대기"가 된다. 사유는
  "'로그인 화면 개선' 결재를 기다리는 중"처럼 앞 기안서를 이름으로 알린다. 자리가 비면 먼저 기다린
  기안서부터 자동으로 이어간다.
- 파일을 고치지 않는 단계(예: UX, UI 명세)는 자리를 잡지 않으므로 순서 대기 중인 기안서도 그 단계까지는
  진행한다.
- 단계가 파일을 고치는지는 Workflow 단계 계약이 정한다. 단계 계약이 없는 단일 동료 요청은 프로젝트에서
  실행하면 파일을 고치는 것으로 본다.
- 기안서를 취소해도 이미 바뀐 파일은 폴더에 남는다. 취소 확인 화면에서 이 사실을 알린다.

### 2. 메시지는 받는 사람과 지금 단계를 기준으로 전달한다

| 상황                                | 처리                                                                                          |
| ----------------------------------- | --------------------------------------------------------------------------------------------- |
| 팀에게 보냄(기본값)                 | 지금 단계 담당이 받는다. 시작 전이면 요청이 된다                                              |
| 지금 단계 담당에게 보냄             | 바로 전달하고 그 단계의 추가 지시로 기록한다                                                  |
| 아직 차례가 오지 않은 동료에게 보냄 | 그 동료의 단계가 시작될 때 메모로 전달한다. 입력창에서 "단풍 차례에 전달돼요"라고 미리 알린다 |
| 이미 끝난 단계의 결과를 뒤집는 내용 | 받은 동료가 판단해 "라떼 단계부터 다시 할까요?"를 사용자 질문(`user_questions`)으로 올린다    |

- 1번 단계에는 뒤집힐 앞 단계가 없으므로 첫 단계 담당과의 대화는 Claude 앱처럼 그대로 이어진다.
- "바로 전달"은 runtime이 실행 중 입력을 지원하면 실행 중에 넣고, 지원하지 않으면 지금 턴이 끝난 직후 넣는다.
  runtime별 지원 여부는 adapter가 확인하며 지원하지 않는 것을 지원하는 것처럼 꾸미지 않는다.
  2026-10-05 확인: Claude Agent SDK는 `Query.streamInput`, Codex app-server는 안정 API `turn/steer`로 실행 중 입력을 지원한다.
- 전달 시점과 받은 동료를 사람의 판단 사실(ADR 012 2절)로 기록한다.

### 3. 결재는 파일이 바뀐 기안서에만 붙는다

- 마지막 단계가 끝났을 때 변경 사실이 있으면 최종 검토(결재 대기)로 간다. 변경 사실이 없으면 결재 없이
  완료로 끝나고 결과를 보여준다. ADR 012 4절 6번 규칙("마지막 단계 → 최종 검토")을 이렇게 좁힌다.
- 변경 사실은 Git 저장소 프로젝트에서는 작업 공간의 시작점 대비 차이(ADR 019 3절), 그 밖의 폴더에서는 runtime의
  파일 변경 event(파일 쓰기·수정 도구, 파일 변경 항목)로 판단한다.
- 사용자가 중간 확인을 요청해 둔 단계(ADR 012 4절 5번)는 변경과 관계없이 멈춘다.

## 결과

- 보드에 "순서 대기" 칸이 생기고 Task 데이터에 대기 사유(앞 기안서)를 기록한다.
- Workflow 단계 계약에 파일 수정 여부가 필수가 된다.
- 결재함에는 파일이 바뀐 기안서와 질문·권한·실패만 모인다. 질문만 한 대화는 결재함에 오지 않는다.
- 입력창에 받는 사람 선택과 전달 시점 안내가 필요하다(ADR 017 4절).

## 재검토 조건

- 프로젝트에서 질문만 하는 단일 동료 요청이 파일 수정 자리를 막는 사례가 잦을 때(읽기 전용 대화 도입)
- runtime 파일 변경 event가 실제 변경을 빠뜨리는 사례가 확인될 때
