# Pixel Office Usability Team

AI Pixel Office를 사용할 법한 10개 페르소나가 feature 또는 전체 제품 여정을 평가하는 로컬 사용성
테스트 팀이다. 연구 진행자가 조건을 정규화하고, 각 페르소나는 자신의 숙련도·목표·제약 안에서 독립적으로
관찰하며, 마지막에 공통 문제와 상충하는 의견을 함께 정리한다.

이 팀의 결과는 실제 사용자 조사 결과가 아니다. `simulation`은 가설 생성용이며, `live`는 허용된 테스트
환경에서 실제 제품을 조작해 얻은 관찰을 포함한다. 어느 방식이든 사람 대상 조사를 대체하지 않는다.

## 시작 명령

다음처럼 요청하면 된다.

```text
pixel-office-usability-team 시작
단위: feature
대상: Task 생성부터 실행, 검토, 후속 요청까지
진행 기간: 3일
실행 방식: simulation
```

전체 여정 예시:

```text
pixel-office-usability-team 시작
단위: 전체
대상: 설치부터 첫 프로젝트와 첫 Task 완료, 재방문까지
진행 기간: 5일
실행 방식: live
환경: 별도 테스트 프로젝트, 가짜 데이터만 사용
```

조건을 일부만 주면 연구 진행자가 아래 기본값을 제안하고, 안전한 범위에서는 바로 시작한다.

| 조건 | 값 | 권장 기본값 |
| --- | --- | --- |
| 단위 | `feature` / `전체` | `feature` |
| 대상 | 기능명·시작점·종료점 | 현재 요청에서 추론 |
| 진행 기간 | 세션 수 또는 일수 | feature 3일, 전체 5일 |
| 실행 방식 | `simulation` / `live` / `hybrid` | `simulation` |
| 참여자 | 10명 또는 하위 집합 | 10명 |
| 환경 | OS, desktop/web, 테스트 프로젝트 | 현재 환경, 격리 데이터 |
| 데이터 정책 | 생성 허용 범위·보존 여부 | 가짜 데이터, 삭제 금지 |
| 중점 질문 | 학습성·효율·오류 복구 등 | 학습성, 막힘, 신뢰, 재방문 |
| 산출물 | 중간 기록·최종 보고서 | 세션 기록 + 최종 보고서 |

## 기간의 의미

- `simulation`: 실제 시간이 흐른 것으로 꾸미지 않는다. Day별 목표와 기억·상태 변화를 시나리오로
  압축 실행하고 `simulated` 증거로 표시한다.
- `live`: Day 1, Day 2처럼 각 체크포인트에 실제 제품을 다시 사용한다. 에이전트가 백그라운드에서 며칠간
  자율 실행되는 것으로 가정하지 않으며, 사용자가 각 세션을 시작하거나 별도 자동화가 필요하다.
- `hybrid`: 핵심 경로는 실제 조작하고 장기 재방문·희귀 오류만 시뮬레이션한다.

## 산출물

- `templates/test-plan.yaml`: 범위, 환경, 기간, 성공 기준
- `templates/session-note.yaml`: 페르소나별 행동·관찰·증거
- `templates/checkpoint.yaml`: 날짜/세션별 누적 변화
- `templates/usability-report.yaml`: 공통 발견, 이견, 심각도, 권고

연구 기록은 기본적으로 대화 또는 사용자가 지정한 경로에만 만든다. production 데이터, 개인 정보, 실제
자격 증명을 사용하지 않는다. 상세 계약은 `instructions/`를 따른다.
