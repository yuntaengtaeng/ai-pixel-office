# 첨부·프로젝트 컨텍스트 UX/구현 계약

상태: 제안 (2026-09-08)

## 조사로 확인한 네이티브 패턴

- Codex/ChatGPT 계열은 `+` 파일 선택, 파일 드래그 앤 드롭, 클립보드에서 복사한 이미지 붙여넣기를 같은 작성 영역에서 제공한다.
- Claude도 파일 열기, 드래그 앤 드롭, 클립보드 이미지 붙여넣기를 지원한다.
- 텍스트를 붙여넣는 것은 계속 메시지 본문이며, 이미지가 클립보드에 있을 때만 이미지 첨부로 해석한다.
- 프로젝트 폴더 연결은 전체 폴더를 자동 업로드/색인한다는 뜻이 아니라, Agent가 필요할 때 해당 작업 범위의 파일을 읽을 수 있게 하는 명시적 workspace scope다.

근거: [OpenAI 이미지 입력 안내](https://help.openai.com/en/articles/8400551-chatgpt-image-inputs-faq/), [Claude 파일 업로드 안내](https://support.claude.com/en/articles/8241126-upload-files-to-claude), [Codex 로컬 파일/프로젝트 안내](https://help.openai.com/en/articles/20001275/).

## 현재 제품과의 차이

- Chat과 Task 작성기는 현재 문자열 메시지만 전송한다.
- Task의 `projectId`는 실행 CWD를 정하지만, 명시적으로 첨부한 파일/이미지를 전달하는 도메인 모델과 HTTP 계약은 없다.
- 따라서 UI에 첨부 칩만 추가하면 Agent가 실제로 읽지 못하는 가짜 경험이 된다.

## 제안하는 사용자 경험

1. 작성 영역에 `파일 추가` 버튼을 두고 여러 파일을 선택할 수 있다.
2. 작성 영역 전체가 드롭존이 되며, 드롭한 파일은 전송 전 미리보기 칩으로 표시한다.
3. 이미지 클립보드 붙여넣기는 이미지 칩으로 표시한다. 일반 텍스트 붙여넣기는 본문에 그대로 들어간다.
4. 전송 전 각 첨부를 제거할 수 있고, 파일명·종류·크기(이미지는 썸네일)를 확인할 수 있다.
5. 프로젝트가 연결된 경우에도 자동으로 모든 파일을 첨부하지 않는다. 사용자가 고른 첨부와 Agent가 실행 중 명시적으로 읽은 파일만 컨텍스트로 취급한다.
6. 세션 재개 시 과거 첨부를 제품이 임의로 프롬프트에 다시 넣지는 않는다. 다만 첨부 원본과 메타데이터는 이력에서 다시 보고 다운로드할 수 있어야 한다.

## 구현 경계 (다음 작업)

```ts
type MessageAttachment = {
  id: string;
  name: string;
  mediaType: string;
  size: number;
  source: "file" | "clipboard-image";
  localPath?: string;
};
```

- Web: 공용 Composer가 picker/drag/paste를 수집하고 전송 전 상태를 관리한다.
- Server: multipart 또는 앱 전용 업로드 계약으로 첨부를 작업/run에 귀속한다. JSON 문자열에 base64를 섞지 않는다.
- Storage: OS가 임의로 비울 수 있는 시스템 temp가 아니라 앱 데이터 아래의 작업별 저장소에 원본을 보존한다. 프로젝트 폴더에는 복사하지 않는다.
- History: Task/Chat의 실행 기록에서 파일명·종류·크기·전송 시점을 보여주고, 권한 검증된 다운로드를 제공한다.
- Runtime adapter: 지원하는 provider에는 명시적 첨부 경로/콘텐츠만 전달한다. 지원하지 않는 경우 전송 전에 이유를 표시한다.
- 보안: 파일명·크기·MIME·경로를 검증하고 workspace 밖 경로를 자동으로 확장하지 않는다.

## 아직 결정해야 하는 충돌

첨부 원본의 보존 기간과 삭제 시점이 정해지지 않았다. 저장 위치는 앱 데이터 아래 작업별 저장소로 확정하고, 다음 정책만 결정하면 된다.

- 작업 삭제 시 첨부도 함께 삭제할지
- workspace 삭제/초기화 시 첨부를 어떻게 처리할지
- 사용자가 직접 삭제할 수 있는지

Provider 세션 재개가 첨부 컨텍스트를 보존하지 않더라도, 제품 이력의 원본 다운로드는 독립적으로 제공한다.

### 권장 보존 기준

- 완료·실패·취소된 Task라도 이력이 남아 있는 동안 첨부를 보존한다. 기간 만료로 자동 삭제하지 않는다.
- 사용자가 Task를 삭제하면 해당 Task의 첨부를 함께 삭제한다.
- Workspace를 삭제하거나 초기화하면 포함된 첨부를 함께 삭제한다.
- 업로드 도중 실패한 고아 파일은 연결되지 않은 시점부터 24시간 후 정리한다.
- 저장 공간이 부족할 때만 설정 화면에서 전체 용량과 삭제 대상을 보여주고 사용자가 직접 정리한다.
